# Community API
All routes under existing `/api/auth/` prefix; existing session/CSRF rules apply.

- GET `community/config/` -> `{skills: [{value,label}], technologies: [{value,label}], interests: [{value,label}], report_reasons: [{value,label}]}`. Skills/technologies use same catalog; interests use project top categories.
- GET/PATCH `community/profile/` -> `{profile: PublicProfile & {discoverable:boolean}}`. Partial edit: bio (max1000), website (http/https or empty), skills (max12 distinct catalog IDs), interests (max8 category IDs), discoverable, invitations_open. Name/username edit remains existing `profile/` API.
- GET `people/?q=&skill=&interest=&page=1` -> `{people: PublicProfile[], count, next_page:number|null, previous_page:number|null}` (12/page). Only active, discoverable, GitHub-linked accounts. Single filters, q max100. Case insensitive Turkish I/İ/ı/i normalized together, other accented letters preserved.
- GET `people/<username>/` -> `{profile: PublicProfile, projects: ProjectSummary[], count, next_page, previous_page}`; public profile even when hidden from discovery or GitHub disconnected. Projects only publicly discoverable active listings; page query supported.
- PublicProfile = `{username, full_name, bio, website, skills:string[], interests:string[], invitations_open:boolean, github_username:string, github_url:string, avatar_url:string}`. No email/phone/birth/gender/id/provider identity payload.
- Existing POST `projects/<uuid>/invitations/` `{username}`: same auth/ownership/eligibility; new invitations fail403 code `invitations_closed` if recipient opts out. Existing pending invitation retries remain idempotent. No new invitation endpoint.
- Existing project config adds `skills`, `technologies`; create/edit accept optional `technologies:string[]`, `required_skills:string[]` (max12 each, catalog only). All project summaries/details include both arrays.
- Existing project discovery adds `q` (title/description), `technology`, `skill` (required_skills), combined with existing filters.
- GET `bookmarks/?page=1` -> `{bookmarks:[{project_id:string, project:ProjectSummary|null, available:boolean}], count,next_page,previous_page}` (12/page). Null summary when current access lost/archived. Only caller's list. GET `projects/<uuid>/bookmark/` -> `{saved:boolean}` requires current visibility. PUT same route `{}` saves idempotently (visibility required); DELETE same route removes idempotently even after access loss -> `{saved:false}`.
- POST `reports/` `{target_type:'project'|'profile', target_id:string, reason:'spam'|'harassment'|'inappropriate'|'misleading'|'other', description:string}`. project target UUID; profile target username. Description 10–2000 trimmed chars. Verified signed-in actor, accessible target; own content prohibited; duplicate pending report (same reporter+target regardless reason) returns existing ID. Response `{report:{id:string,status:'received',created_at:string},created:boolean}`,201 new/200 duplicate. Private reporter identity, no read/list/admin/moderation API, no provider effects. Records persist until account/target deletion; cascades remove associated reports.
