# Normal auth teknik kararları

- PostgreSQL kalıcı kullanıcılar, session registry (opaque UUID, key hash/key yalnız sunucu içi), iptal durumu ve security version tutar. Redis Django cache session içeriği ve atomik deneme sayaçları/tek kullanımlı geçici token içeriğinden sorumludur. Kalıcı iptal kaydı her authenticated istekte kontrol edilir; Redis kaybı logout/yeniden link istemeyi gerektirir, PostgreSQL fallback ile güvenlik atlanmaz. Redis arızası fail-closed 503.
- Redis sayaçları atomik Lua ile sabit 15 dakika pencere: hesap başına 5 başarısız giriş, IP başına 30 giriş denemesi; bekleme pencere sonuna kadar. IP yalnız REMOTE_ADDR; reverse proxy güven sınırı deployment kontrolüdür, istemci X-Forwarded-For güvenilmez. E-posta gönderimi atomik 60 saniye aralık + 5/saat; reset IP/hesap limiti ayrıca.
- Token'lar kriptografik rastgele, yalnız hash anahtarıyla Redis'te, amaç/kullanıcı/adres/security version bağlı; tek kullanım atomik tüketim, DB mutation transaction ve user row lock. SQLite testleri PostgreSQL yarış kilidini doğrulamaz.
- Parola politikası Unicode büyük/küçük harf/rakam, sembol, boşluksuz 8–20; Django yaygın şifre listesi + yerel bilinen ele geçirilmiş parola hash listesi (kapsam açıkça belgelenir, tüm dünya sızıntılarını kapsadığı iddia edilmez). Dış parola sorgusu veya canlı kişisel veri aktarımı yok.
- SMTP ortam değişkenleri, TLS/SSL seçimi, timeout, sabit frontend URL. Kayıt gönderim başarısızlığı 503 ve rollback; reset hesap sayımını önlemek için genel yanıt + güvenli operasyonel log. Diğer gönderimler hatayı gizlemez.
- Session cookie HttpOnly/Secure/SameSite=Lax; CSRF Secure/SameSite=Lax; varsayılan same-origin Next proxy. Explicit CSRF anonim POST dahil. Kimlik/session yanıtları cache edilmez.
- Yerel .venv ve paketler bu görev için kullanıcı tarafından izinli. Testler yalnız SQLite memory, Redis fake ve locmem SMTP. Dinleyen backend/frontend, Docker, gerçek DB/Redis/SMTP ve deploy yok.
- Başlangıç kontrolleri: git status temiz, branch main, origin GitHub. Eski backend/frontend active kayıtları sonuçsuz: failed olarak korundu. İlk graph validate iki kez başarısız oldu (eski gate ilişkileri); yeni arşiv review düğümleriyle düzeltildi, son validate passed. Adapter dosyası codex.json; ilk codex.md okuması bulunamadı ve gerçek dosyadan düzeltildi.
- Teknik referanslar: https://docs.djangoproject.com/en/5.2/topics/http/sessions/ ; https://docs.djangoproject.com/en/5.2/ref/csrf/ ; https://nextjs.org/docs/app/api-reference/config/next-config-js/rewrites . Çalışma zamanı uyumu ayrıca doğrulanacak.

## Hazırlık bağımsız audit düzeltmeleri
- Parola deneme sayacı yalnız login değil tüm password proof işlemlerinde paylaşılır: reauthenticate ve password/change old_password dahil.
- Reset admission sayacı normalize adres başına 5/saat, IP başına 30/15 dakika; bilinmeyen adresler aynı sayılır ve aynı 429 döner. SMTP sonucu anonim genel cevabı değiştirmez.
- Önceki graph validate düzeltmesinde legacy review ready düğümleri için CLI sync/validate tutarsızlığı görüldü: sync failed-target review'ı hazır yapıyor, validator ready için yalnız done arıyor. Sistemi değiştirmeden review active duruma geçirilip arşiv denetimi yapılır; orijinal failed statüler korunur. Run genel status eski başarısız denemeler yüzünden blocked kalabilir; aktif kapsamın tamamlanması yeni düğümlerin sonuçlarıyla raporlanır.
- B uygulama ayrıntısı: aynı hesaptaki eşzamanlı password proof 30 saniyelik Redis lease ile 429 reddedilir; hash öncesinde başarısız deneme bütçesi rezerve edilir, doğru şifrede temizlenir. Session süreleri registry ve cookie üzerinde mutlak bitiştir. Redis lease gerçek zaman/atomiklik testi not_verified.

## E proxy IP entegrasyon düzeltmesi
Varsayılan mod REMOTE_ADDR; rastgele istemci XFF güvenilmez. Per-client mode explicit iki taraflı AUTH_PROXY_SECRET (en az32 karakter) ve yalnız ingress'in üzerine yazdığı header'ı tanımlayan frontend AUTH_CLIENT_IP_HEADER ile açılır. Gerçek ingress header güvenilirliği deploy kontrolüdür; key config ile iki taraf uyumlu olmalı. Frontend tek canonical IP'yi okuyup HMAC-SHA256 imzalar. İmza metni dört satır: `ip\nunix_seconds\nHTTP_METHOD\n/api/auth/path/`. Başlıklar X-First-Client-IP, X-First-Client-Time, X-First-Client-Signature. Backend secret aktifken bütün /api/auth/ isteklerinde imza/method/path/IP ve ±60s tazelik kontrolü zorunlu; eksik/geçersiz assertion 403 code invalid_proxy_assertion. Counter anahtarı doğrulanmış IP; secret yokken bu başlıklar yok sayılır. Frontend assertion'ı incoming headers'tan kopyalamaz. Header config eksik/invalid durumda per-client mode fail-closed503; secret'lar yalnız ortamda.
E revision dosya sahipliği: backend_writer yalnız FIRST/backend; frontend_writer yalnız FIRST/frontend. Ayrı dosyalara eşzamanlı yazım yalnız aynı E integration düzeltmesi için, F/G aşaması erken başlatılmadı. Vercel trusted ingress header dokümanı: https://vercel.com/docs/headers/request-headers ; x-forwarded-for yalnız gerçek ingress overwrite güvencesiyle yapılandırılır, self-hosted açık server için otomatik güvenilmez.
